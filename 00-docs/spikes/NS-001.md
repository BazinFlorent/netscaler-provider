### 6. NITRO authentifié depuis un pod

#### Récupérer l’IP CPX et transmettre les credentials via un Secret

La première commande récupère l’IP Docker du conteneur CPX. La seconde lit son mot de passe initial et le transmet directement à Kubernetes, sans l’afficher dans le terminal.

```bash
CPX_IP="$(docker inspect poc-netscaler-cpx \
  --format '{{with index .NetworkSettings.Networks "kind"}}{{.IPAddress}}{{end}}')"

docker exec poc-netscaler-cpx cat /var/deviceinfo/random_id \
  | jq -Rs --arg endpoint "http://${CPX_IP}:9080" '{
      apiVersion: "v1",
      kind: "Secret",
      metadata: {
        name: "ns001-nitro-credentials",
        namespace: "default"
      },
      type: "Opaque",
      stringData: {
        CPX_PASSWORD: rtrimstr("\n"),
        CPX_ENDPOINT: $endpoint
      }
    }' \
  | kubectl --context kind-netscaler-provider create -f -
```

`/var/deviceinfo/random_id` est un fichier contenant le mot de passe initial généré par CPX. Son nom ne signifie pas que le mot de passe est un entier, et `cat` ne génère pas de nouvelle valeur : il lit celle déjà stockée. Le contenu est conservé en texte par CPX. Si le mot de passe est changé, il faudra utiliser les credentials courants ; ne pas supposer que ce fichier représente toujours le mot de passe actif.

Le Secret est temporaire pour ce test. Aucun credential n’est enregistré dans le dépôt ni dans ce CR. Ne pas exécuter les commandes avec `set -x` activé.

#### Créer le pod de test authentifié

Le pod injecte le Secret dans son environnement. Les headers d’authentification sont fournis à curl via son entrée standard, sans inscrire le mot de passe dans le manifeste du pod ni dans les arguments de curl.

```bash
kubectl --context kind-netscaler-provider create -f - <<'EOF'
apiVersion: v1
kind: Pod
metadata:
  name: ns001-nitro-auth
  namespace: default
spec:
  restartPolicy: Never
  containers:
    - name: check
      image: curlimages/curl:8.12.1
      envFrom:
        - secretRef:
            name: ns001-nitro-credentials
      command: ["sh", "-c"]
      args:
        - |
          printf 'header = "X-NITRO-USER: nsroot"\nheader = "X-NITRO-PASS: %s"\n' "$CPX_PASSWORD" |
            curl --config - --fail-with-body --silent --show-error \
              --connect-timeout 5 --max-time 10 \
              "${CPX_ENDPOINT}/nitro/v1/config/nsversion"
EOF

kubectl --context kind-netscaler-provider wait \
  --for=jsonpath='{.status.phase}'=Succeeded \
  pod/ns001-nitro-auth --timeout=60s

kubectl --context kind-netscaler-provider logs ns001-nitro-auth
```

**Attendu :** pod Succeeded et réponse JSON avec `errorcode: 0`, `message: Done` et build `73.30.nc`.  
**Observé :** réponse NITRO avec `errorcode: 0`, `message: Done`, `severity: NONE` ; version `NetScaler NS14.1: Build 73.30.nc`, datée du 27 juillet 2026, 64-bit. La sortie de la commande wait n’a pas été fournie dans la preuve partagée.  
**Résultat : PASS pour l’accès NITRO authentifié depuis le cluster.** Le réseau et l’authentification fonctionnent depuis un pod ; cela ne teste pas encore un provider Crossplane ni l’écriture de ressources ADC.

### 7. Mode de licence Express et capacité autorisée

**But :** distinguer les fonctionnalités autorisées, le mode de licence et la capacité de débit effective déclarée par CPX. Cette vérification ne mesure pas le débit réellement atteint sous charge.

#### Fonctionnalités licenciées via NITRO

```bash
CPX_PASSWORD="$(docker exec poc-netscaler-cpx \
  cat /var/deviceinfo/random_id)"

curl -sS --max-time 10 \
  -H 'X-NITRO-USER: nsroot' \
  -H "X-NITRO-PASS: $CPX_PASSWORD" \
  http://localhost:19080/nitro/v1/config/nslicense \
  | jq

unset CPX_PASSWORD
```

**Observé :** `errorcode: 0`, `lb: true`, `ssl: true`, `cs: true`, `isplatinumlic: true`, `licensingmode: Pooled`, `daystoexpiration: 0`. Le champ `lb: true` confirme que le load balancing est autorisé par la licence ; cette réponse seule ne prouve ni le mode Express ni le débit alloué. Les champs Pooled et daystoexpiration ne sont pas interprétés comme une preuve de licence payante ou expirée.

#### Capacité effective et serveur de licences

```bash
docker exec poc-netscaler-cpx \
  /var/netscaler/bins/cli_script.sh "show ns capacity"

docker exec poc-netscaler-cpx \
  /var/netscaler/bins/cli_script.sh "show licenseserver"
```

**Attendu :** capacité effective de 100 Mbit/s, cohérente avec CPX Express pour cette version, et aucun serveur de licences externe configuré.

**Observé :**

```text
show ns capacity
Actualbandwidth: 100   MaxVcpuCount: 2   Edition: Platinum
Unit: Mbps   Bandwidth: 0   Maxbandwidth: 40000
Minbandwidth: 20   Instancecount: 0
Done

show licenseserver
Done
```

#### Synthèse et interprétation

| Résultat | Interprétation |
|---|---|
| `lb: true` | Le load balancing est autorisé par la licence effective |
| `Actualbandwidth: 100`, `Unit: Mbps` | CPX déclare une capacité effective de **100 Mbit/s** |
| `show licenseserver` ne liste aucun serveur | Aucun serveur de licences externe configuré |
| Image Quay, sans licence externe fournie dans le lab | Déploiement cohérent avec **Express appliqué par défaut**, selon la documentation NetScaler |
| `Edition: Platinum` | Niveau de fonctionnalités exposé ; ce champ seul ne prouve pas l’utilisation d’une licence payante |
| `Maxbandwidth: 40000` | Ne correspond pas au débit effectif alloué de cette instance ; retenir `Actualbandwidth: 100` pour le relevé de capacité |

La [documentation de licence CPX](https://docs.netscaler.com/en-us/cpx/current-release/cpx-licensing.html) indique qu’Express est appliqué par défaut aux instances téléchargées depuis Quay et que sa capacité passe à 100 Mbit/s à partir de 14.1-17.38. Notre image 14.1-73.30, l’absence de serveur de licences et la capacité déclarée sont cohérentes avec ce fonctionnement.

**Résultat : PASS — Mode Express déduit du déploiement Quay sans serveur de licences externe, conformément à la documentation. Capacité effective déclarée : 100 Mbit/s. Débit réel non mesuré.** Le mode Express est une conclusion croisant configuration, documentation et observations ; aucune sortie partagée n’affiche explicitement le libellé Express.
